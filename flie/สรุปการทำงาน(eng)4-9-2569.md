## 2. Root Cause Analysis (RCA)

A forensic deep-dive into the AI pipeline revealed five distinct architectural and algorithmic bottlenecks responsible for the latency and erratic behavior:

### Root Cause 1: Raw Ultra-High Resolution Ingestion Choking CPU ONNX Runtime
* **Symptom:** Facial detection and feature extraction took 15 to 30 seconds per pass.
* **Mechanism:** Police mugshots and raw mobile camera uploads (often 3000 × 4000 pixels or larger) were fed directly into the InsightFace SCRFD detector without pre-scaling. Because the system runs on standard CPU execution providers (`CPUExecutionProvider`), the convolutional operations across millions of pixels caused extreme CPU core saturation and thermal throttling.
* **Remedy:** Implemented adaptive pre-scaling to standard 640px (`max(h, w) <= 640`), which perfectly aligns with the SCRFD optimal anchor grid. Facial crops are extracted at the native $112 \times 112$ ArcFace resolution, maintaining 100% embedding fidelity while slashing compute time to **~0.35s**.

### Root Cause 2: Mugshot Height Ruler Digits Misclassified as Thai National IDs
* **Symptom:** Known criminal mugshots failed to match against the face database; the system instead responded with irrelevant ID card records.
* **Mechanism:** Police mugshots feature height measurement calibrations on the background wall (`150`, `140`, `130`, etc.). The OCR engine detected these digits, and an unvalidated fallback in `app/modules/id_card/parser.py` (`return all_digits[:13]`) concatenated them into fake 13-digit numbers (`0150140140301`). Consequently, `classifier.py` erroneously tagged mugshots as `idcard`, diverting the query away from face recognition.
* **Remedy:** Removed the unvalidated digit slicing fallback and enforced strict Modulo 11 Thai National ID checksum validation alongside mandatory official header keywords (`"บัตรประจำตัวประชาชน"`).

### Root Cause 3: Inverted Classifier Pipeline Overhead
* **Symptom:** Every image submitted to the system suffered an unavoidable 2.5 to 5.0 second initial delay before any face detection took place.
* **Mechanism:** The multi-modal classifier (`app/core/classifier.py`) ran PaddleOCR unconditionally across the entire image to search for text before performing facial analysis.
* **Remedy:** Re-architected the classifier into a **Fast-Path Hierarchical Architecture**. The ultra-fast SCRFD face detector (running in < 0.15s) now executes first. If a human face is found in standard portrait or square aspect ratios (`aspect_ratio < 1.30`), it is classified as `face` immediately, **bypassing the OCR engine completely**.

### Root Cause 4: Cascade Loop on Sub-Threshold or Innocent Faces
* **Symptom:** Non-suspect faces or genuine suspects with slightly lower scores took 10+ seconds and often generated false license plate warnings.
* **Mechanism:** In `app/core/router.py`, if a face did not exceed an overly restrictive similarity threshold of `0.65`, the router treated the search as failed and cascaded the image down to license plate OCR and ID card OCR.
* **Remedy:** Calibrated the ArcFace cosine similarity threshold to **0.52** (optimal for `buffalo_l` ResNet-50 ArcFace) and added a **short-circuit mechanism**: when a human face is clearly detected (`detected_face == True`), the search pipeline immediately terminates without falling through to vehicular or document OCR.

### Root Cause 5: Windows Console Encoding Crash on Unicode Emojis
* **Symptom:** Intermittent initialization failures causing InsightFace to fail and fallback to legacy Haar Cascades.
* **Mechanism:** Raw Unicode emojis (`\u2705`) embedded in `print()` statements caused `charmap UnicodeEncodeError` crashes on default Windows `cp1252` console streams.
* **Remedy:** Replaced console print statements with safe `logger.info()` routines and configured `PYTHONIOENCODING="utf-8"`.

        norm = np.linalg.norm(emb)
