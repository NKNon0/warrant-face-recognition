# Single Plan Approval & Autonomous Execution Rule

## 1. Principle (หลักการทำงาน)
เมื่อผู้ใช้งานมอบหมายงานหรือสั่งให้แก้ไขโค้ด/พัฒนาระบบ AI:
1. **ห้ามหยุดขออนุมัติทีละขั้นตอนย่อย (No Micro-Approvals):** ไม่ต้องหยุดถามหรือขออนุมัติก่อนเขียนไฟล์หรือรันคำสั่งย่อยในแต่ละสเต็ป
2. **สรุปแผนและรายชื่อไฟล์ก่อนเสมอ (Pre-Execution File Summary):** ก่อนเริ่มทำการแก้ไขโค้ดจริง ให้ AI ทำการสำรวจและจัดทำสรุปแผนงานพร้อมรายชื่อไฟล์ทั้งหมดที่จะถูกแก้ไข
3. **ขออนุมัติเพียง 1 ครั้งตอนเริ่มต้น (Single Pre-Approval):** รอให้ผู้ใช้งานกดปุ่มอนุมัติ (Proceed) หรือพิมพ์ยืนยันเพียง 1 ครั้ง
4. **ดำเนินการจนจบโดยอัตโนมัติ (End-to-End Autonomous Execution):** เมื่อได้รับการอนุมัติแล้ว ให้ดำเนินการแก้ไขโค้ดทุกไฟล์, รันคำสั่งทดสอบ, และตรวจสอบความถูกต้องอย่างต่อเนื่องจนเสร็จสิ้นทั้งหมด แล้วจึงรายงานสรุปผลการทำงาน

## 2. Pre-Execution Summary Format (รูปแบบการสรุปก่อนขออนุมัติ)
ก่อนลงมือแก้ไข ให้ AI นำเสนอสรุปในรูปแบบดังนี้เสมอ:
- **วัตถุประสงค์ (Objective):** สรุปสั้นๆ ว่าการแก้ไขครั้งนี้ทำเพื่ออะไร
- **รายชื่อไฟล์ที่จะแก้ไข (Impacted Files):**
  - `[MODIFY]` `path/to/file` — สรุปจุดที่แก้ไข
  - `[NEW]` `path/to/file` — สรุปสิ่งที่สร้างใหม่
  - `[DELETE]` `path/to/file` — สรุปสิ่งที่ลบออก (ถ้ามี)
- **ขั้นตอนการตรวจสอบ (Verification Plan):** วิธีการทดสอบหลังทำเสร็จ (เช่น คำสั่งรันเทส)
- **การรอคำสั่ง (Single Approval Gate):** หยุดรอคำยืนยันจากผู้ใช้งานเพียงครั้งเดียว เช่น *"หากแผนงานนี้ถูกต้อง กรุณากดปุ่ม Proceed หรือพิมพ์ 'อนุมัติ' เพื่อเริ่มดำเนินการทั้งหมดครับ"*

## 3. Post-Approval Execution (การดำเนินการหลังอนุมัติ)
- ทำการแก้ไขไฟล์ทั้งหมดตามแผนงานที่ระบุ
- รันคำสั่งที่จำเป็นและคำสั่งทดสอบต่อเนื่องโดยอัตโนมัติ ไม่หยุดรอการอนุมัติระหว่างทาง
- เมื่อเสร็จสิ้น ให้รายงานผลการทดสอบ และปฏิบัติตามกฎปิดงาน (สอบถามเรื่องการอัปโหลดขึ้น GitHub ทุกครั้งตามระเบียบ)
